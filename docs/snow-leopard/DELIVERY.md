## 构建

本地不运行编译、Gradle、测试或打包。所有检查在 GitHub Actions：

- `snow-ci.yml`：推送 main、codex 分支或 PR，执行新规则／状态机／AI 协议及相关课表导入单测、Lint、Debug 打包；模拟器矩阵 API 30、31、34、35、36 验证持久化、无效写入原子性和首页启动。产物含 APK、SHA-256 和报告。最低系统按用户最新要求设为 Android 11（API 30）。
- `snow-release.yml`：手动触发或推送匹配应用版本的 `snow-v*` 标签，执行单测、Lint、R8、资源压缩、签名打包；上传签名 APK、SHA-256、源码 ZIP 和版本说明，暂不自动公开发布 Release。

- 外部 PR 不接触签名 Secrets；`pull_request_target` 未使用。上游官网 Pages 作业在此仓库禁用。

## 实现入口与数据

- `domain/guard`：固定模板、规则编译、冲突合并、端点和时间区间、带写入前快照的声音状态机。
- `data/guard`：DataStore 保存规则／模板／可信设备；同步提交的 SharedPreferences 保存恢复所有权；独立 Room 保存最多 300 条执行事件、AI 对话与待确认草稿。
- `feature/guard`：首页、规则／模板编辑、权限／可信设备、AI 配置／对话、前台服务／闹钟／快捷磁贴。
- `github/.../feature/guard`：Shizuku 固定 AIDL 操作，仅媒体音量与完整活动路由查询；商店渠道使用能力缺失实现。
- 课表仍使用上游 Room 47 与全部迁移。覆盖导入前在同一数据库事务中复制为“雪豹导入快照”课表；恢复时激活并重命名快照，不覆盖后续编辑。快照可在原课表管理中检查／删除。

固定模板不可覆盖；自定义模板单独保存。空规则不启用保护。模板的音量是上限，不主动调高。临时放行 5 分钟；手动保护 1 小时；结束本次按当前重叠时段的结束时间放行。全天不添加提前／延后。

AI 配置与原课表文件导入共用，密钥由已有 Android Keystore 机制保存。自然语言返回新增规则草稿；持久化前校验，保存前检查基线指纹，重复确认幂等。会话最多保留最近 12 条，每次输入最多 6000 字；可停止和清空。AI 不授权耳机，不直接执行系统操作。自填视觉能力是声明，需在课表图片导入中实际验证。

## 必须如实呈现的限制

- 这是待 CI 和真机验证的首版实现，不能把源码存在视为构建通过。
- 没有系统级硬锁。开启锁定后通过回调及保护期 1 秒纠正检查限制媒体音量；系统休眠、OEM 冻结和强制停止可能延迟或阻止执行。
- 普通模式只能识别连接设备，不能证明全部播放器的实际路由，因此不会凭连接状态放行耳机。增强模式依赖系统隐藏的完整多路由接口，不可用时保持限制；旧系统可能始终无法自动放行。
- 路由不明时不自动恢复旧媒体音量，避免把耳机音量恢复到扬声器；用户可在结束保护后手动调节。恢复记录不记录或恢复播放状态。
- 暂停依赖播放器媒体会话；固定音量设备不支持控制；铃声、通知和震动常被系统联动，图书馆模板不控制第三方应用自行产生的触觉反馈。
- 新版系统将应用勿扰映射为所属自动规则；旧版静音模式可能联动全局勿扰，需测试用户已有勿扰不会被解除。
- 教务适配优先复用内置正方、青果、URP；所有学校入口标记待验证。不能以通用脚本存在宣称所有学校可用。
- 既有 SleepDown 课表备份与新保护数据分开。系统自动备份禁用，避免导出声音运行快照和密钥。
- Android 模拟器不能替代实际耳机、厂商后台、铃声联动和耗电验收。

## 真机验收表

每台设备记录型号、Android/OEM 版本、权限、模式、播放器与耳机型号：

1. 锁屏和息屏前后：保护边界、跨午夜、重启、时区变更、精确闹钟撤权。
2. 普通播放器、短视频、网页、游戏：静音／限音、调音量纠正、支持和不支持暂停。
3. 可信／非可信耳机、手表、多设备、手动切回扬声器和断连：不得仅因蓝牙连接而放行。
4. 用户已有勿扰／静音、保护中手动修改、离开保护：只恢复仍由本应用控制的状态。
5. 导入单双周、调课、停课、自定义作息，确认日周显示与保护时间一致；保存失败不丢原课表。
6. 关闭网络／AI 失败／停止任务／过期草稿：已有离线规则不改变。
7. 记录边界触发和断连纠正延迟、是否漏音、连续保护耗电；未测设备不显示可靠认证。

首次交付没有实际手机验收结果；验收后将设备记录独立附在本目录。
